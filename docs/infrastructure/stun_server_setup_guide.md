# 🚀 **Руководство по настройке STUN сервера для WebRTC**

**Дата создания:** 25.08.2025  
**Статус:** 🚨 **КРИТИЧЕСКИ ВАЖНО**  
**Цель:** Решение проблемы с WebRTC аудио через настройку STUN сервера

---

## 📋 **Обзор проблемы**

**Текущая ситуация:** WebRTC звонки инициируются, UI работает корректно (сигналинг, таймеры, статусы соединения), но **аудио не передаётся** между пользователями.

**Причина:** Отсутствуют STUN/TURN серверы для NAT traversal, что препятствует установке peer-to-peer соединений.

**Решение:** Настройка STUN сервера на production сервере 5.8.76.33.

---

## 🎯 **Что такое STUN сервер простыми словами?**

**STUN сервер** - это как **почтальон для интернета**. Представь ситуацию:

1. **Ты дома** (в локальной сети) - у тебя есть внутренний адрес, например 192.168.1.100
2. **Твой друг в другом городе** (в другой сети) хочет тебе позвонить
3. **Проблема:** Друг не знает твой внешний адрес в интернете (5.8.76.33) и через какую "дверь" (порт) к тебе подключаться
4. **Решение:** STUN сервер говорит твоему приложению: "Эй! Твой внешний адрес в интернете 5.8.76.33, и вот через какую дверь (порт) тебя можно найти!"

**Без STUN сервера:** Твои пользователи не смогут найти друг друга для звонков, потому что они "спрятаны" за роутером (NAT).

### **Шаг 4: Настройка конфигурации** ⚙️

Создайте файл конфигурации:

```bash
sudo nano /etc/turnserver.conf
```

**Что такое nano:**
- **nano** - простой текстовый редактор в командной строке
- Проще чем vim, подходит для начинающих
- Работает прямо в терминале

**Что делает команда:**
- **`sudo`** - создаёт файл с правами администратора
- **`/etc/turnserver.conf`** - стандартное место для конфигурации coturn
- **`nano`** - открывает редактор

**Как работать с nano:**
- **Стрелки** - перемещение по тексту
- **Ввод текста** - просто печатай
- **Ctrl+X** - выйти
- **Y** - сохранить изменения
- **Enter** - подтвердить имя файла

**Содержимое конфигурации (только STUN):**

```conf
# Основные настройки
listening-port=3478          # Порт, на котором сервер будет слушать подключения
listening-ip=0.0.0.0        # Слушать на всех сетевых интерфейсах (все IP адреса)
external-ip=5.8.76.33       # Твой внешний IP адрес сервера в интернете

# Только STUN (без TURN для MVP)
no-auth                      # Без авторизации (проще для начала, небезопасно для продакшена)
no-tls                       # Без шифрования TLS (проще для начала)
no-dtls                      # Без шифрования DTLS (проще для начала)

# Логирование
verbose                      # Подробные логи (видно что происходит)
fingerprint                  # Добавляет отпечаток в STUN сообщения (для совместимости)

# Ограничения
max-allocate-lifetime=3600   # Максимальное время жизни соединения в секундах (1 час)
max-bps=128000              # Максимальная скорость в бит/с (128 Кбит/с на соединение)
bps-capacity=0               # Без ограничений на общую пропускную способность сервера

# Логи
log-file=/var/log/turnserver.log  # Файл для записи логов (для отладки)
```

**АЛЬТЕРНАТИВНАЯ КОНФИГУРАЦИЯ (если первая не работает):**

```conf
# Основные настройки
listening-port=3478
listening-ip=0.0.0.0
external-ip=5.8.76.33

# Только STUN
no-auth
no-tls
no-dtls

# Логирование
verbose
fingerprint

# Ограничения
max-allocate-lifetime=3600
max-bps=128000

# Логи
log-file=/var/log/turnserver.log
```

**Объяснение каждой настройки:**

**`listening-port=3478`:**
- **3478** - стандартный порт для STUN протокола
- Сервер будет слушать подключения на этом порту
- Аналогия: это как номер квартиры в доме

**`listening-ip=0.0.0.0`:**
- **0.0.0.0** означает "слушать на всех сетевых интерфейсах"
- Если у сервера несколько IP адресов, он будет отвечать на всех
- Аналогия: как если бы ты поставил звонок на все двери квартиры

**`external-ip=5.8.76.33`:**
- **5.8.76.33** - твой внешний IP адрес в интернете
- STUN сервер будет сообщать клиентам именно этот адрес
- Аналогия: это твой "почтовый адрес" в интернете

**`no-auth`:**
- Отключает проверку логина/пароля
- Проще для тестирования, но небезопасно
- Аналогия: как открыть дверь без замка

**`no-tls` и `no-dtls`:**
- Отключает шифрование соединений
- Проще для отладки, но трафик не защищён
- Аналогия: как говорить по телефону без шифрования

**`verbose`:**
- Включает подробные логи
- Видно все действия сервера
- Аналогия: как включить детальное логирование в приложении

**`fingerprint`:**
- Добавляет уникальный отпечаток в STUN сообщения
- Нужно для совместимости с некоторыми клиентами
- Аналогия: как подпись в конце письма

**`max-allocate-lifetime=3600`:**
- Соединения автоматически закрываются через 1 час
- Экономит ресурсы сервера
- Аналогия: как автоматическое отключение неактивных пользователей

**`max-bps=128000`:**
- Ограничивает скорость одного соединения до 128 Кбит/с
- Достаточно для голосовых звонков
- Аналогия: как ограничение скорости на дороге

**`log-file=/var/log/turnserver.log`:**
- Все логи записываются в файл
- Легко найти и прочитать ошибки
- Аналогия: как запись всех действий в журнал

**Как сохранить в nano:**
1. Нажми **Ctrl+X** (выйти)
2. Нажми **Y** (сохранить изменения)
3. Нажми **Enter** (подтвердить имя файла)

### **Шаг 6: Настройка файрвола** 🔥

```bash
# Установка UFW (если не установлен)
sudo apt install -y ufw

# Открытие порта 3478 UDP для STUN
sudo ufw allow 3478/udp

# Проверка правил
sudo ufw status numbered

# Включение файрвола (если не включен)
sudo ufw enable
```

**Что такое файрвол:**
- **Файрвол** - это как охранник на входе в здание
- Проверяет все входящие и исходящие подключения
- Блокирует подозрительные или неразрешённые соединения
- Аналогия: как Windows Defender или антивирус

**Что такое UFW:**
- **UFW** (Uncomplicated Firewall) - простой файрвол для Ubuntu
- Легко настраивается, понятные команды
- Аналогия: как упрощённая версия Windows Firewall

**Что делает `sudo apt install -y ufw`:**
- Устанавливает файрвол UFW
- Создаёт базовые правила безопасности
- Аналогия: как установить программу-файрвол

**Что делает `sudo ufw allow 3478/udp`:**
- **`allow`** - разрешить подключения
- **`3478`** - на порт 3478
- **`udp`** - по протоколу UDP (не TCP)

**Почему UDP, а не TCP:**
- **STUN** использует протокол UDP
- **UDP** быстрее для передачи медиа данных
- **TCP** медленнее, но надёжнее
- Аналогия: UDP как SMS (быстро, но может потеряться), TCP как звонок (медленнее, но надёжнее)

**Что делает `sudo ufw status numbered`:**
- Показывает все правила файрвола с номерами
- Видно, какие порты открыты/закрыты
- Аналогия: как список разрешённых гостей на входе

**Что должно показать:**
```
Status: active

     To                         Action      From
     --                         ------      ----
[ 1] 22/tcp                    ALLOW IN    Anywhere
[ 2] 3478/udp                  ALLOW IN    Anywhere
[ 3] 22/tcp (v6)              ALLOW IN    Anywhere (v6)
[ 4] 3478/udp (v6)            ALLOW IN    Anywhere (v6)
```

**Ключевые моменты:**
- **`Status: active`** - файрвол включён и работает
- **`[ 2] 3478/udp ALLOW IN Anywhere`** - порт 3478 UDP открыт для всех
- **`Anywhere`** - разрешены подключения с любого IP адреса

**Что делает `sudo ufw enable`:**
- Включает файрвол
- Все правила начинают действовать
- Аналогия: как нажать кнопку "Включить" в настройках файрвола

**Важно:** После включения файрвола все неразрешённые подключения будут заблокированы!

### **Шаг 7: Тестирование STUN сервера** 🧪

```bash
# Проверка прослушивания порта
sudo netstat -tulpn | grep 3478

# Тест с помощью curl (должен вернуть STUN response)
curl -v stun://5.8.76.33:3478

# Проверка логов
sudo tail -f /var/log/turnserver.log
```

**Что делает `sudo netstat -tulpn | grep 3478`:**
- **`netstat`** - показывает сетевые соединения и порты
- **`-t`** - TCP соединения
- **`-u`** - UDP соединения  
- **`-l`** - только слушающие порты
- **`-p`** - показывать имя программы
- **`-n`** - показывать номера портов вместо названий
- **`grep 3478`** - фильтрует только строки с портом 3478

**Что должно показать:**
```
udp        0      0 0.0.0.0:3478            0.0.0.0:*                           1234/turnserver
```

**Объяснение вывода:**
- **`udp`** - протокол UDP
- **`0.0.0.0:3478`** - слушает на всех интерфейсах, порт 3478
- **`0.0.0.0:*`** - принимает подключения с любого IP и порта
- **`1234/turnserver`** - процесс ID 1234, программа turnserver

**Что делает `curl -v stun://5.8.76.33:3478`:**
- **`curl`** - программа для отправки HTTP/STUN запросов
- **`-v`** - подробный вывод (verbose)
- **`stun://5.8.76.33:3478`** - STUN протокол на твоём сервере

**Что должно произойти:**
- curl попытается подключиться к STUN серверу
- Сервер должен ответить STUN сообщением
- В выводе будет видно обмен данными

**Если сервер работает, увидишь что-то вроде:**
```
* Connected to 5.8.76.33 (5.8.76.33) port 3478 (#0)
* STUN request sent
* STUN response received
```

**Что делает `sudo tail -f /var/log/turnserver.log`:**
- **`tail`** - показывает последние строки файла
- **`-f`** - следит за файлом в реальном времени (follow)
- **`/var/log/turnserver.log`** - файл с логами STUN сервера

**Что должно показать:**
```
0: log file opened: /var/log/turnserver.log
0: Starting STUN/TURN server...
0: Listening on 0.0.0.0:3478
0: STUN server is running
```

**Как выйти из просмотра логов:**
- Нажми **Ctrl+C** для остановки слежения
- Логи будут продолжать записываться в файл

## 🚨 **Возможные проблемы и решения**

### **Проблема 1: Сервис не запускается**

```bash
# Проверка ошибок
sudo journalctl -u coturn -f

# Проверка конфигурации
sudo turnserver -c /etc/turnserver.conf --dry-run
```

**Что делать:**
1. **Запусти `sudo journalctl -u coturn -f`** - покажет ошибки запуска
2. **Запусти `sudo turnserver -c /etc/turnserver.conf --dry-run`** - проверит конфигурацию без запуска
3. **Исправь ошибки** в конфигурации
4. **Перезапусти сервис:** `sudo systemctl restart coturn`

**Частые ошибки:**
- Неправильный IP адрес в `external-ip`
- Неправильные права доступа к файлу конфигурации
- Конфликт портов (другая программа использует 3478)

### **Проблема 2: Порт не открыт**

```bash
# Проверка правил файрвола
sudo ufw status numbered

# Принудительное открытие порта
sudo ufw allow 3478/udp
```

**Что делать:**
1. **Проверь статус файрвола:** `sudo ufw status`
2. **Если файрвол не активен:** `sudo ufw enable`
3. **Открой порт:** `sudo ufw allow 3478/udp`
4. **Проверь правила:** `sudo ufw status numbered`

**Частые ошибки:**
- Файрвол не включён
- Неправильный протокол (TCP вместо UDP)
- Конфликт с другими правилами

### **Проблема 3: STUN не отвечает**

```bash

sudo ip route show

# Тест локального подключения
telnet localhost 3478
```

**Что делать:**
1. **Проверь, что сервер слушает:** `sudo netstat -tulpn | grep 3478`
2. **Проверь локальное подключение:** `telnet localhost 3478`
3. **Проверь внешнее подключение:** `curl -v stun://5.8.76.33:3478`
4. **Проверь логи:** `sudo tail -f /var/log/turnserver.log`

**Частые ошибки:**
- Сервер не запущен
- Неправильный IP адрес в конфигурации
- Блокировка на уровне провайдера
